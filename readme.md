# TeamFinder

## Структура запуска

В проекте представлены следующие сервисы Docker Compose:

- `server` — Django-приложение;
- `db` — PostgreSQL;
- `seed` — заполнение базы демонстрационными данными.

------

## Подготовка к запуску

### 1. Клонирование репозитория

```bash
git clone https://github.com/gowkjwwqw/team-finder-ad.git
cd team-finder-ad
```

------

### 2. Виртуальное окружение

1. **Создайте виртуальное окружение (в папке проекта):**
   ```bash
   python3 -m venv venv
   ```

2. **Активируйте окружение:**

    - **Windows (PowerShell):**
      ```bash
      venv\Scripts\Activate.ps1
      ```
    - **Windows (cmd):**
      ```bash
      venv\Scripts\activate
      ```
    - **Linux/Mac:**
      ```bash
      source venv/bin/activate
      ```

3. **Установите зависимости из `requirements.txt`:**
   ```bash
   pip install -r requirements.txt
   ```

   После установки в окружении будут доступны все нужные библиотеки Django-проекта.

------

### 3. Создание `.env`

Файл `.env` содержит конфиденциальные настройки проекта — ключ Django, параметры БД и другие переменные.  

Особое внимание обратите на строчку `TASK_VERSION=`. 
Добавьте число, которое соответствует вашему варианту задания. 
Этот параметр определяет, какие шаблоны использовать для сайта (из папок `templates_var1`/`templates_var2`/`templates_var3`).
Лишние две папки не из вашего варианта можно удалить.

В репозитории есть пример `.env_example`, который нужно скопировать и заполнить:

```bash
cp .env_example .env
```

После этого откройте `.env` и укажите свои значения.  

| Переменная            | Назначение                                                                                                                                                 |
|-----------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **DJANGO_SECRET_KEY** | Секретный ключ Django, используемый для подписи cookie и токенов. Можно сгенерировать при помощи `get_random_secret_key` из `django.core.management.utils` |
| **DJANGO_DEBUG**      | Режим отладки. Установите `True` во время разработки.                                                                                                      |
| **POSTGRES_DB**       | Имя базы данных PostgreSQL, которую будет использовать Django.                                                                                             |
| **POSTGRES_USER**     | Имя пользователя PostgreSQL.                                                                                                                               |
| **POSTGRES_PASSWORD** | Пароль пользователя PostgreSQL.                                                                                                                            |
| **POSTGRES_HOST**     | Адрес сервера БД. В случае локальной разработки localhost.                                                                                                 |
| **POSTGRES_PORT**     | Порт подключения к БД (по умолчанию `1122`).                                                                                                               |
| **TASK_VERSION**      | Номер варианта вашего задания. Используется для определения набора HTML-шаблонов.                                                                          |

------

### 4. Запуск проекта через Docker Compose

Для работы приложения **TeamFinder** используется база данных **PostgreSQL**. Сборка и запуск приложения производится следующей командой:

```bash
docker-compose up -d --build
```

Сборка и запуск приложения c заполнением тестовыми данными:

```bash
docker-compose --profile seed up -d --build
```

После запуска приложение будет доступно по адресу:

```bash
http://localhost:8000
```

Остановка контейнеров производится следующей командой:

```bash
docker-compose down
```

Полная остановка с удалением volumes:

```bash
docker-compose down -v
```
------

После этого база данных будет доступна по адресу `localhost:1122`.  
Нужно будет использовать эти же параметры в файле `.env`.

### 6. Проверка качества кода

В проекте настроен линтер flake8.

Локальный запуск линтера:
```bash
flake8 .
```

Принятые правила:
* максимальная длина строки: 100 символов;
* исключены служебные каталоги и миграции.

------

### 7. Проведение CI

В репозитории настроен GitHub Actions workflow, который автоматически выполняет проверку кода

Workflow находится в файле: `.github/workflows/main.yml`
